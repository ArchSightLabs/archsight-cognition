# Source Quality Guide

Use this reference when `cogx-research-brief` needs to judge source quality.

## Source Types

- First-party: official documentation, product pages, standards, repositories, release notes, filings, papers by the original authors.
- Primary evidence: source code, public datasets, issue trackers, changelogs, benchmark results, direct interviews, firsthand observations.
- Secondary interpretation: blog posts, media coverage, analyst notes, community summaries, marketplace pages.
- Weak signals: search popularity, social posts, star counts, install counts, comments, anecdotes.

## Weighting Rules

- Prefer first-party and primary evidence for factual claims.
- Use secondary interpretation to understand framing, not to establish facts by itself.
- Treat weak signals as directional only; never equate them with real demand or quality.
- When sources disagree, report the disagreement instead of forcing a single conclusion.
- Always separate verified facts, reasonable inferences, and open questions.

## Minimum Citation Fields

For each cited source, capture:

- Title or project name.
- URL.
- Source type.
- Publication date if available.
- Access date for webpages.
- What claim the source supports.
- What the source does not prove.
