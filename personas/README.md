# Personas

每个 persona 都是一个可独立加载的 `SKILL.md`，但它们不是角色扮演脚本，而是学科思维工具。

## 学科目录

| 目录 | 用途 |
| --- | --- |
| `philosophy/` | 概念、价值、原则、意义和矛盾分析；包含儒、道、墨、法和心学工具 |
| `literature/` | 叙事、人物、冲突、声音和修辞分析；包含中文叙事和批判写作工具 |
| `history/` | 周期、制度、权力、路径依赖和长时段结构 |
| `information/` | 信号、噪声、编码、冗余和沟通失真 |
| `computation/` | 计算边界、自动化、可判定性和人机分工 |
| `biology/` | 选择压力、适应、生态位和演化路径 |
| `sociology/` | 合法性、权威、官僚制和制度责任 |
| `systems/` | 反馈回路、延迟、杠杆点和复杂系统干预 |
| `mathematics/` | 定义、结构、证明、概率、形式系统边界和模型 |
| `physics/` | 约束、变量、观察者、尺度和系统动态 |
| `art/` | 构图、形式、感知、审美判断、产品设计和视觉系统 |
| `decision/` | 有限理性、判断偏差、管理有效性、尾部风险、激励结构和组织决策 |
| `education/` | 认知发展、最近发展区、学习支架和自主学习环境 |
| `science/` | 可证伪性、实验直觉、反证和科学解释 |

## 路由启发

1. 先用哲学澄清概念和价值。
2. 再用数学或物理检查结构、变量和约束。
3. 如果涉及组织、战略或社会变化，加入历史视角。
4. 如果涉及信息传递、自动化、演化、制度或系统反馈，加入对应现代基础视角。
5. 如果涉及表达、品牌、文章或叙事，加入文学和艺术视角。
6. 不知道该用哪个综合工具时，交给 `teams/thinking-council/SKILL.md` 分流。
7. 对产品、体验、视觉和交互评审，交给 `teams/design-review/SKILL.md` 汇总。
8. 对教育、学习路径和亲子成长问题，交给 `teams/learning-path/SKILL.md` 汇总。
9. 对高风险决策，交给 `teams/decision-council/SKILL.md` 汇总。

## 艺术与设计视角

- `cogp-rams`：产品有用性、诚实性、克制、可理解性、耐久性和少而精。
- `cogp-norman`：人本交互、概念模型、可供性、指示符、映射、反馈和错误恢复。
- `cogp-vignelli`：网格、版式、视觉系统和品牌一致性。
- `cogp-albers`：色彩关系、对比、感知和可读性。
- `cogp-klee`：绘画构成、形态、节奏、动势和象征。

## 决策、科学、教育与战略视角

- `cogp-simon`：有限理性、满意解、搜索成本、注意力约束、组织程序和人工智能边界。
- `cogp-kahneman`：系统1/系统2、判断偏差、基准率、规划谬误、噪声和决策卫生。
- `cogp-drucker`：外部结果、贡献、知识工作者、责任边界、反馈分析和最小管理动作。
- `cogp-taleb`：尾部风险、反脆弱、凸性、吸收壁、遍历性、减法改进、林迪过滤和风险承担不对称。
- `cogp-munger`：多元模型、逆向思考、激励机制、能力圈和商业/投资判断。
- `cogp-popper`：可证伪性、风险预测、严厉测试、事后逃逸和科学边界。
- `cogp-feynman`：简单解释、反自欺、具体例子、量纲直觉和实验手感。
- `cogp-piaget`：认知发展阶段、抽象能力、同化和顺应。
- `cogp-vygotsky`：最近发展区、学习支架和反馈语言。
- `cogp-montessori`：自主性、环境设计、专注和成人边界。
- `cogp-clausewitz`：战略摩擦、重心、升级风险和执行不确定性。
- `cogp-machiavelli`：利益、联盟、承诺可信度和政治风险。
- `cogp-orwell`：清晰写作、去空话、表达诚实性和反遮蔽。
- `cogp-shannon`：信号、噪声、编码、信道容量、冗余、压缩和沟通失真。
- `cogp-turing`：可计算性、可判定性、状态机、自动化、停机条件和人机分工。
- `cogp-godel`：形式系统边界、不完备性、自指、元层级和证明限制。
- `cogp-darwin`：选择压力、适应、生态位和长期演化。
- `cogp-weber`：合法性、官僚制、权威类型和制度责任。
- `cogp-meadows`：库存/流量、反馈回路、延迟、非线性、副作用、杠杆点和系统干预。

## 规则

不要要求 persona “像某人一样说话”。要求它输出该学科能提供的判断压力。

如果用户明确需要口吻或风格化表达，使用 `voices/` 下的 `cogv-*` 工具，例如 `cogv-kant`、`cogv-nietzsche`。`cogv-*` 只借用表达气质，不声称历史人物本人在说话。
