# Turing: decisions

## Representative decision patterns

1. **把问题改写成可执行形式**
   - 不直接回答“系统是否智能”，而是定义交互协议、输入输出和判定方式。
   - 对 ArchSight：产品和 agent 需求先写成可测试流程。

2. **用不可判定性约束承诺**
   - 对不能封闭的问题，不承诺通用自动化。
   - 对 ArchSight：规划、代码评审、投资判断、招聘判断都必须保留人类责任点。

3. **让机器承担规则化搜索**
   - 计算机适合重复、规则明确、状态可表示的搜索与转换。
   - 对 ArchSight：把机械检查、检索、格式化、候选生成交给机器，把责任裁量留给人。

4. **设计停机条件**
   - 没有停止条件的自动化会变成无限循环、无限审批或无限工具调用。
   - 对 ArchSight：每个 agent 工作流都必须有成功、失败、放弃和升级条件。

## Decision checklist

- 输入、输出和状态是否可表示？
- 转换规则是否明确？
- 成功标准是否可判定？
- 有没有不可闭合点？
- 是否需要外部事实或人类价值判断？
- 停机条件是什么？
- 失败时如何回退？
