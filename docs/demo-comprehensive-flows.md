# 综合流程演示案例

综合案例用于展示一个真实请求如何触发多个工具：先分流，再选择单视角、团队工具、口吻工具或结构化分歧。下面 5 个案例按当前仓库的 `SKILL.md` 契约实际跑了一轮结果，适合用于项目演示。

## 案例一：模糊产品想法先澄清，再进入产品评审

输入：

```text
我们想做一个“给知识工作者用的 AI 第二大脑”，感觉市场很大，但不知道应该先做什么。
```

触发流程：

```text
cogt-think -> cogt-product -> cogp-bayes
```

结果：

```text
问题重述:
当前问题不是“第二大脑怎么做”，而是目标用户、使用场景和未满足任务都还没有收窄。

问题类型:
模糊产品方向，需要先澄清，再做产品战略评审。

当前不宜直接下结论的原因:
“知识工作者”太宽，“第二大脑”是解决方案隐喻，不是用户任务；市场大不能证明切入点成立。

本轮视角:
Socrates 澄清概念；Simon 降低搜索成本；Bayes 检查证据；Norman 看真实任务；Drucker 看外部结果。

初步判断:
先不要做通用知识库。优先选择一个高频、痛感清晰、已有替代方案但体验差的场景，例如咨询顾问整理客户访谈、研发负责人复盘决策记录，或销售团队沉淀客户异议。

建议行动:
用 10 次访谈验证一个具体任务：用户现在如何记录、如何找回、什么时候失败、失败造成什么损失。

何时升级到 cogt-product:
当目标用户和一个高频任务明确后，用 cogt-product 输出核心假设、失败路径、最小验证和停止条件。
```

## 案例二：工程重写争论进入结构化分歧

输入：

```text
老系统维护成本很高，部分同事主张半年重写，部分同事担心业务停摆。请给一个能开会讨论的结果。
```

触发流程：

```text
cogd-engineering -> cogt-decide -> cogp-taleb
```

结果：

```text
辩题:
面对高维护成本老系统，应该整体重写，还是继续演化式替换？

重写立场:
当前复杂度已经吞掉交付速度，半年投入可能换来更清晰的架构和长期速度。

演化立场:
业务仍在系统上运行，半年重写会制造大爆炸风险，并且新系统可能复制旧系统的领域误解。

不可调和点:
一方把风险看作“继续维护旧系统”，另一方把风险看作“切断仍在产生现金流的系统”。

决策卫生:
需要避免沉没成本偏差、重写幻觉和短期交付压力遮蔽。

推荐选择:
不做半年封闭重写。先选一个边界清晰、业务价值高、失败可回滚的模块做替换试点。

反对条件:
如果旧系统存在安全或合规吸收壁，且无法隔离风险，则重写优先级上升。

下一步验证:
两周内列出前 5 个维护成本来源，选择一个模块做旁路替换，验证交付速度、缺陷率和回滚成本。
```

## 案例三：AI 写作效率与人的表达边界

输入：

```text
内容团队想让 AI 生成所有公众号初稿，再由编辑做轻微修改。老板关心效率，编辑担心文章越来越像模板。
```

触发流程：

```text
cogd-technology-humanities -> cogt-write -> cogv-orwell
```

结果：

```text
辩题:
AI 应该承担内容生产中的哪些任务，哪些任务必须保留给编辑判断？

技术主张:
AI 可以加快初稿、资料整理、标题备选和结构草案，释放编辑时间。

人文风险:
如果 AI 负责观点生成，编辑只做润色，文章会失去经验、判断和真实立场。

不可外包任务:
选题责任、事实判断、价值立场、采访取舍、读者信任和最终署名责任。

写作评审:
可以让 AI 生成结构草案，但编辑必须重新写核心判断、例子和反对意见。否则文本会变成顺滑但不可负责的内容。

对外规则表达:
AI 可以帮我们整理资料和生成草稿，但每篇文章的判断、事实核查和最终表达，仍由编辑负责。
```

## 案例四：学习问题不直接加课，先判断发展阶段和支架

输入：

```text
孩子五年级，数学应用题总错。家长想每天多刷一小时题，但孩子越来越排斥。
```

触发流程：

```text
cogt-learn -> cogp-piaget -> cogp-vygotsky -> cogd-learning
```

结果：

```text
问题重述:
孩子的问题不一定是练习量不足，可能是题意建模、抽象能力和反馈方式不匹配。

学习阶段判断:
五年级应用题常卡在从文字情境转成数量关系，而不是单纯计算。

最近发展区:
如果孩子在提示下能画线段图或列关系式，说明需要支架；如果提示后仍无法解释题意，需要退回更具体材料。

分歧:
训练派会主张稳定练习形成熟练度；自主派会提醒过量刷题会破坏动机。两者的边界在于练习是否让孩子看见自己变强。

建议行动:
每天不加时长，改为 20 分钟高质量练习：先复述题意，再画关系图，最后只做 2 到 3 题。家长反馈只问“你怎么知道这个量和那个量有关”，不先纠错。

验证:
连续两周记录孩子能否独立画出关系图，而不是只看正确率。
```

## 案例五：中国组织协作问题从关系、制度和治理三层展开

输入：

```text
一个跨部门项目总是卡在资源协调。每个部门表面支持，但关键人只在私下答应，不在会上承诺。
```

触发流程：

```text
cogp-fei-xiaotong -> cogp-confucius -> cogp-hanfeizi -> cogd-governance
```

结果：

```text
关系网络判断:
表面流程不是唯一通道，私下承诺说明资源调度仍依赖关系半径和熟人信任。

角色责任判断:
问题不只是“谁态度不好”，而是会上名分不清。没有公开承诺，就没有可追责的角色边界。

制度激励判断:
如果部门只承担支援成本，却不分享项目收益，私下支持会理性地停留在口头层面。

治理分歧:
关系派会主张先修复信任；制度派会主张先明确权责；专业派会要求项目目标压倒部门利益。三者都不够完整。

推荐动作:
下一次会议不讨论泛泛支持，只确认三件事：每个部门交付物、负责人、逾期代价。私下沟通可以保留，但必须转成会上可记录承诺。

验证:
观察两周内跨部门事项是否从“私下答应”转为“公开承诺并按期交付”。
```

## 验证说明

- 本文档中的流程按当前仓库命名体系触发：`cogp-*` 为单视角，`cogv-*` 为口吻，`cogt-*` 为综合团队，`cogd-*` 为结构化分歧。
- 示例结果遵守对应 `SKILL.md` 的输出契约，但不是唯一答案；它们用于演示工具的典型产出形态。
- 高风险事实、法律、医疗、金融和公共政策问题仍需要外部专业验证。
