# Debates

`debates/` 是 ArchSight Cognition 的结构化分歧入口。

它用于长期、反复出现、没有单一正确答案的问题：人生意义、技术与人、工程秩序、工作职业、学习教育、知识真实、治理权力。它不替代 `teams/` 的综合评审，也不替代 `personas/` 的单一学科视角，而是把一个稳定领域沉淀成可调用的 `cogd-*` skill。

`team` 讲究合作和综合，最后要收束成一个可执行判断。`debate` 讲究冲突和压力测试，最后不必伪造共识，但必须说明分歧会怎样改变行动、责任和验证路径。

## 什么时候用 debate

| 场景 | 使用 |
| --- | --- |
| 问题已经是一个具体方案选择 | `cogt-decide` |
| 问题还没成型，需要先分流 | `cogt-think` |
| 需要单一学科视角做压力测试 | `cogp-*` |
| 需要风格化表达 | `cogv-*` |
| 需要围绕长期张力展开结构化分歧 | `cogd-general` 或领域 `cogd-*` |

## Debate 与 Team 的区别

| 维度 | `cogt-*` team | `cogd-*` debate |
| --- | --- | --- |
| 目标 | 综合多视角，形成可执行判断 | 放大真实冲突，暴露选择代价 |
| 视角关系 | 合作、互补、主持人收束 | 对立、交锋、主持人保留张力 |
| 输出重点 | 共识、盲点、综合判断、下一步 | 对立立场、最强反对意见、不可调和点、行动分叉 |
| 是否收敛 | 应该收敛到暂定判断 | 不强行收敛，只给边界和下一步验证 |
| 适合问题 | 方案评审、写作评审、设计评审、学习路径 | 价值冲突、长期议题、立场压力测试、责任争议 |

## 核心议题

当前默认 debate 包含 1 个通用入口和 7 个领域入口。具体话题只作为案例演示，不作为默认命令入口。

| Skill | 领域 | 覆盖面 |
| --- | --- | --- |
| `cogd-general` | 通用结构化分歧 | 任意长期议题、价值冲突、责任争议 |
| `cogd-life` | 人生与意义 | 意义、自由、关系、死亡、欲望、承诺 |
| `cogd-technology` | 技术与人 | AI、自动化、工具、进步、责任 |
| `cogd-engineering` | 工程与秩序 | 架构、技术债、边界、演化、治理 |
| `cogd-work` | 工作与职业 | 职业、财富、能力、安全感、组织责任 |
| `cogd-learning` | 教育与学习 | 自主、塑造、训练、保护、筛选 |
| `cogd-knowledge` | 知识与真实 | 事实、证据、叙事、模型、有效性 |
| `cogd-governance` | 治理与权力 | 专家、公众、权力、责任、合法性 |

## 命名规则

- 目录放在 `debates/<topic>/SKILL.md`。
- frontmatter `name` 使用 `cogd-<short-name>`。
- `cogd` 表示 cognition debate。
- 领域名称要稳定、可复用，不要为具体话题新增 debate skill。
- 通用入口固定使用 `debates/general/SKILL.md` 和 `cogd-general`。
- 具体话题放在 `debates/examples/`，不要做成默认入口。

## 新增标准

新增 debate 前先问：

1. 这个议题是否会反复出现，而不是一次性任务？
2. 是否存在真实分歧，而不是只有常识答案？
3. 是否能调用 3 到 5 个已有 persona 形成互补压力？
4. 是否能形成至少 2 个强对立立场，而不是只有轻微偏好差异？
5. 输出是否能帮助用户看清行动分叉、责任边界或下一步验证？

从 `templates/debate-skill.md` 开始新增。
